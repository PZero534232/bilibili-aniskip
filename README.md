# Bilibili 番剧 OP/ED 跳过（AniSkip / Anime Skip 数据源）

给 B 站播放器加一个能力：**自动跳过番剧的片头 / 片尾 / 总集篇回顾**，包括 B 站官方没有时间戳的「用户上传」搬运番。

> Auto-skip anime OP/ED on Bilibili, including user-uploaded episodes that have no official timestamps. Uses the AniSkip and Anime Skip databases (keyed by anime ID + episode number), so it works regardless of which site hosts the video. Chinese / romaji / Japanese / English / shorthand search supported.

## 为什么需要它

B 站只给**番剧区正版番剧**提供官方片头片尾时间戳。UP 主搬运、字幕组投稿的番剧（B 站标记为「用户上传」）没有任何 OP/ED 数据，于是：

| 现有思路 | 为什么不够 |
| --- | --- |
| 解析弹幕里的「空降 / 正片开始」 | 冷门番、老番、弹幕关闭／清空的视频里根本没人刷 |
| 众包标记（如 SponsorBlock） | 对冷门新番、新上线剧集没有覆盖 |
| 固定秒数（每集都跳 90 秒） | 必然错。同一部番每集的 OP 起点都不一样（实测 1995 年的 EVA 各集 OP 起点就不同） |
| 等 B 站官方 | 官方只处理正版番剧区，搬运稿永远等不到 |

**关键思路**：AniSkip 和 Anime Skip 这两个动画时间戳数据库是按「**番剧 ID + 集数**」组织数据的，跟你在哪个网站看没关系。所以「B 站没有时间戳」这件事，可以用外部数据补上。

## 特性

- ⏭ **自动跳过 OP / ED / 回顾** —— 三个独立开关，回顾默认关（很多人想看）
- 🔍 **怎么搜都能中** —— 中文名、罗马字、日文原名、英文名、简写（`Re:0`）都行
- 📺 **多季连播合集** —— 一个视频塞 60 个分P、横跨 5 季也能自动按分段对齐数据库条目（一段可以包含多个季度）
- 🔗 **手动绑定是一等公民** —— 标题乱码 / 没有番名 / 自动认错时，搜一次绑一次，整个合集每集复用
- 🛡 **默认不自动识别** —— 普通视频零请求、零干扰，绝不误伤
- 🫧 **状态胶囊** —— 播放器右上角常驻，随时看识别状态、一键绑定、一键进设置
- ↩️ **跳错能撤回** —— 每次跳过后有 8 秒的「撤回」窗口

## 使用

### 状态胶囊

打开任意 B 站视频页，播放器右上角会出现一个胶囊：

| 胶囊显示 | 含义 |
| --- | --- |
| `● 番剧跳过 · 未识别` | 没认出这是番剧（默认状态） |
| `● 未找到集号` / `标题无番名` | 认出是番剧但缺信息 → 点「绑定」手动指定 |
| `● 已加入「不是番剧」名单` | 你标记过这个视频不是番剧 |
| `● 葬送的芙莉莲 第3集　12 段` | 识别成功，3 段可跳时间戳 |

点胶囊上的 **绑定** 手动指定番剧，点 **⚙** 进设置。不想看到它就在设置里关掉「未识别时也显示胶囊」。

### 自动识别（默认关闭）

设置里的「自动识别」有三档：

- `off` —— **默认**。不做任何自动识别，普通视频完全不触发。手动绑定过的番剧仍然生效（绑过就代表你要它跳）
- `ask` —— 自动识别，命中后在胶囊上显示，由你决定要不要跳
- `auto` —— 自动识别 + 置信度足够时直接跳

### 手动绑定

标题乱码、没有番名、认错番的时候用：

1. 点胶囊上的「绑定」
2. 在搜索框里输番名（中文 / 罗马字 / 日文 / 英文 / 简写都行），点「搜索」；或者点「用标题自动填」
3. 从候选里选中正确的番剧 —— 如果是多季连播合集，脚本会自动推算季边界并显示出来
4. 填「当前是第几话」：填**这个合集里的序号**。比如合集共 32 个视频、你在看第 21 个，就填 21，脚本会自己算出它是第几季第几话
5. 保存。默认作用范围是整个合集的全部视频

### 设置项

| 设置项 | 默认 | 说明 |
| --- | --- | --- |
| 自动识别 | `off` | 见上文 |
| 跳过 OP | 开 | |
| 跳过 ED | 开 | |
| 跳过回顾 Recap | **关** | 总集篇的回顾片段 |
| 跳过「融进正片」的 OP/ED | **关** | 有些番没有独立 OP 段，OP 和画面融在一起播（每集还可能不一样），跳过会切掉正片内容 |
| 撤回提示秒数 | `8` | 跳过后「撤回」按钮停留多久，0 = 不显示 |
| 显示跳转提示 | 开 | 跳转时弹提示 |
| 优先用合集单集标题 | 开 | UP 主在合集里改过的标题往往比原始标题干净 |
| 未识别时也显示胶囊 | 开 | 关掉则普通视频上完全无痕，入口在油猴菜单 |

## 它是怎么认出番剧的

```
标题 → 抽出候选番名（引号「」《》里的优先）
     → 候选打分排序（表意文字数量 − 噪声词 − 括号残片 …）
     → 中文名走 Bangumi 桥换成日文原名
     → AniList 一次拿到 AniList ID + MAL ID
     → 若是多季连播合集，沿 relations 推出季链
     → AniSkip + Anime Skip 双源取时间戳，合并去重
     → 区间校验 + 置信度打分 → 决定跳 / 提示 / 沉默
```

两个容易踩的坑，这个脚本处理了：

- **AniList 不能当中文检索用。** 它只认恰好写在条目 `synonyms` 里的中文，直接搜「葬送的芙莉莲」是 0 条。所以中文名先走 Bangumi（`api.bgm.tv`）拿日文原名，再用日文原名去 AniList 查。
- **UP 主的标题里，真实番名通常在全角引号里**（`「」`、`《》`）。整条标题直接拿去搜会搜回完全无关的番。

## 隐私

- 只用公开只读 API，不带任何账号信息，不收集、不上传任何数据
- 设置、绑定、缓存全部只存在本地（`GM_setValue`）
- 请求域名：`api.aniskip.com`、`api.anime-skip.com`、`graphql.anilist.co`、`api.bgm.tv`、`api.bilibili.com`

## 已知限制

- 数据库里没有的番（很新的、太冷门的、OVA、部分国产番）识别不到 —— 会显示「未识别」，不会瞎跳
- 有些番的 OP 是融进正片画面里的（每集位置都不同），跳过就会切掉正片，所以这类区间默认**不跳**
- 需要一个能对上的番名。标题里完全没有番名时，请手动绑定
- 搬运的剧场版 / 合集视频可能对不上数据库条目

## 常见问题

**Q：会误跳正片吗？**
默认 `off` 完全不自动识别；`auto` 模式要过置信度门槛才跳；每次跳过后 8 秒内可以点「撤回」回到原位。

**Q：为什么打开了却什么都不跳？**
看胶囊上的提示文字。`未识别` = 标题没认出番剧，用「绑定」。`没找到集号` = 标题里没有集数，绑定面板里手动填一下。`这一话不跳` = 数据库里这一集没有可用时间戳。

**Q：换视频 / 切分P 之后要重新弄吗？**
不用。B 站是单页应用，脚本会检测地址和分P变化自动重新识别。绑定过的番剧整个合集都覆盖。

**Q：缓存存在哪？能清吗？**
番剧识别结果、时间戳都会本地缓存，加速后续识别。设置面板里有「清空缓存」。

## 实现说明

- UI（胶囊 / 面板 / 提示）走 Shadow DOM，不与 B 站自己的 CSS 打架
- 面板里的文本输入控件**放在 light DOM，用 `<slot>` 投影进影子树**。因为 Shadow DOM 会把向外传播的事件 `target` 重定向成影子宿主 `div`，B 站「正在输入就不响应快捷键」的判断会失效，表现为在搜索框里打 `q` 触发点赞
- 面板打开期间在 `window` 捕获阶段兜底拦截按键，避免打字触发播放器快捷键
- 面板里所有关键样式用内联而非依赖注入的 `<style>`，万一页面 CSP 拦截样式注入，面板至少还能显示和点击
- 测试：`test/bilibili-aniskip.test.js` 是自建的 DOM / GM / 网络桩，193 项用例覆盖标题清洗、集号抽取、时长打分、区间校验、双源合并、多分P锚点推算、多季对齐、自动识别开关、黑名单、手动绑定优先级。运行：

```bash
node test/bilibili-aniskip.test.js
```

## 更新日志

### 0.4.4
- 修复**「撤回」之后还是会被自动跳过**：撤回时把「本集已跳过这段」的记录删掉了，而轮询是 50ms 一次、撤回又把播放头送回区间内部，于是下一轮立刻重新跳过 —— 点了等于没点。现在记录保留（这一集这段不再自动跳，换集／换视频时自动复位），撤回也回到**原来那一秒**（以前为了绕开这个自激，会退回 1 秒前）
- 修复撤回后**没有任何反馈**：新弹出的「已撤回」提示会被旧 toast 的清理逻辑一起抹掉
- 新增设置「**跳过偏移（秒）**」：在数据库给的时间戳上再挪一点。正数＝多跳（跳过 OP 后的黑屏／静帧），负数＝少跳（保留 OP 尾巴）；最多减到片段起点，不会倒着跳
- 「撤回提示秒数」默认值 8 秒 → **4 秒**（停留太久挡住画面），老配置会自动迁移

### 0.4.3
- 修复**多季合集里「第几段配哪一季」配错**的问题。典型稿件：一个视频装了「第三季 1–16 + 第四季 1–19」，在候选里选第 3 季却说「合集第 2 话 → 第一季第 2 话」，选第 4 季又说「→ 第二季第 2 话」——**取的是错误季的时间戳**
  - 现在**分P标题自己写的季号就是锚点**：「第三季1」这一段从数据库的第 3 季条目开始配。以前只按累计话数从家族最早一季往后数，碰到「只投了后几季」的稿件必然错位
  - 顺带修了两个让上一条失效的隐性 bug：数据库条目的季号读不出来（「3rd season」这种序号写在 season 前面的写法不认；季链里的条目名是字符串却被当成对象读）
  - 季链沿续集关系展开时不再按跳数砍断（长番要 4 跳才够得到第 1 季，原来卡在 3 跳会少一季）
  - 分P标题**没写季号**时仍然退回原来的累计话数贪心，不影响老稿件
- 没对上数据库条目的分段现在**一律不跳**（以前只要凑出了条目就照跳，会跳到错误的季上）
- 末尾的花絮／预告（没有季号、没有话号、时长明显偏短，如「1分钟」）不再算进分段，避免整段话数对不上导致整季失效
- 校验跳转区间时会带上视频实际时长：超过视频长度的区间直接丢弃，99 秒的彩蛋片段不会被误跳
- 老绑定里由旧算法算出的季链会自动忽略（`chainVer` 已升到 4），重开面板保存一次即可

### 0.4.2
- 修复「**单独发一季**」的稿件被误判成多季连播：「第三季】全12话」是「第 3 季，共 12 话」的意思，之前被当成「N季…N话」的多季信号，于是单季投稿也会弹出没用的「季边界」面板
- 修复季链**漏掉最早的几季**导致集号整体错位：从第 3 期出发时，沿续集关系只能收到「第 2 期 + 第 3 期」（祖父辈永远补不进来），于是「合集第 1 话」被算成第 2 期第 1 话。**这会让脚本取错季的时间戳，不只是显示问题**
- 修复「第三季」被认成**第一季**：番名基础名和第一季完全相同时，相似度满分会把第一季排到第一，现在会按标题里的季号纠偏
- 标题点名了多季（如「第二季+第三季」）时，季链只收这几季，绝对集号从点名的那一季起算
- 老绑定里由旧算法算出的季链会被自动忽略（按 `chainVer` 判定），不用担心历史错链继续生效
