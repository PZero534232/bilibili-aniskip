# 本地「手动标记 OP/ED 帧」功能设计

> 修订（2026-10-16）：ED 结束标记与标记入口位置已改，见 `2026-10-16-local-op-ed-ed-end-and-settings-ui-design.md`。

- 日期：2026-10-16
- 状态：待评审
- 范围：`bilibili-aniskip` userscript（`F:\dsh\bilibili-aniskip`）

## 1. 背景与目标

冷番 / 新番在云端数据源（AniSkip / Anime Skip）里往往**没有时间戳**，导致脚本无法跳 OP/ED。本功能让用户**手动标记** OP/ED 的起始帧，脚本靠**视觉指纹匹配（认帧）**自动识别并跳过，且在**同一部番的其它集里复用**。

## 2. 核心决策（已与用户确认）

| 决策点 | 结论 |
| --- | --- |
| 识别信号 | **认画面**（视觉指纹），不认声音 |
| OP 怎么跳 | 认「OP 开始帧」→ 按 OP 时长（结束 − 开始）从检测点跳到 OP 结束 |
| ED 怎么跳 | 认「ED 开始帧」→ 跳到结尾 |
| 存储 | **本地**（GM storage），按绑定番剧 key |
| 换 OP/ED | 重新标记 → 追加新一套指纹（旧指纹自动区分哪一套在播，无需删） |
| 优先级 | 云端时间戳优先；云端没有时，才用本地指纹兜底 |

## 3. 前提与风险（已实测通过）

- **实测结论（2026-10-16）**：B 站播放器用 MSE（`<video>.src` 是 blob URL），但 MediaSource 是 CORS 干净的 —— 直接对当前 `<video>` `drawImage` + `getImageData` 能读到像素（实测 `R=40`）。对 MSE 而言 `crossOrigin` 与污染无关，**无需注入、无需 patchVideoCORS**。
- 抓帧失败（例如将来 B 站改动）→ `captureFrameHash` 返回 null，检测循环静默降级为「不跳」，不崩。
- **兜底**：若哪天读不到像素，整个「认帧」方案退回「认时间」（按 OP 时长 / ED 时长复用），避免卡死。

## 4. 标记交互（方案 A）

- 在**油猴菜单**（胶囊空间有限，优先菜单）加三个动作：
  - 「标 OP 开始」—— 抓当前帧算指纹 + 记当前时间
  - 「标 OP 结束」—— 只记当前时间
  - 「标 ED 开始」—— 抓当前帧算指纹（时间仅用于调试）
- 用户**暂停**到目标那一帧 → 点对应动作 → 脚本抓帧 / 记时间。
- 触发条件：仅当「已绑定 / 已识别、但云端无时间戳」时显示；否则不出现，避免误导。
- 标记完成给出 toast 确认，并立即写入本地存储。

## 5. 指纹与匹配算法

### 5.1 抓帧
- 把当前 `<video>` 帧画到离屏 canvas（需 `crossOrigin="anonymous"`），缩到 8×8 灰度，得到 64 位 **aHash**（平均哈希）；可选再算 pHash 增强抗干扰。

### 5.2 匹配
- 播放中每 **0.25s** 抽一帧算哈希，与存储指纹算 **Hamming 距离**。
- 判定「认到了」需同时满足：
  1. 距离 `< 阈值`（初始 **≤10 / 64**，可调）；
  2. **连续 ≥2 次采样命中**（约 0.5s），防单帧误判。
- 若实测误判多，升级为「窗口指纹」（标记点前后各 0.5s 的连续哈希序列比对）。

### 5.3 采样成本
- 每 0.25s 一次 8×8 降采样 + 哈希，开销可忽略；只在「有本地指纹待匹配」时才开循环，不常驻。

## 6. 存储格式

GM key：`aniskip.localSegs.<bindingKey>`，值为 JSON：

```json
{
  "ops": [ { "hash": "0f3a…", "start": 0.0, "end": 90.0 } ],
  "eds": [ { "hash": "1b7c…" } ]
}
```

- `ops[]`：多套 OP 指纹（换 OP 后追加）；`start`/`end` 为标记时该套 OP 的开始/结束时间（秒），**时长 = `end - start`**。
- `eds[]`：多套 ED 指纹（换 ED 后追加）；ED 结束即视频结尾，无需存结束时间。
- 命中哪一套，就按那一套的时长从检测点起跳；帧指纹自身即可区分「现在是哪一套 OP/ED」，无需按集编号。

## 7. 检测与跳过集成

1. 复用现有 `intervals` 机制开一个轻量采样循环（仅当本地指纹非空）。
2. 抽帧 → 算哈希 → 与 `ops[]`/`eds[]` 全部指纹比对。
3. 命中 OP 指纹 → 复用现有 `performSkip`，从检测点跳到 `检测点 + (end - start)`；命中 ED 指纹 → 跳到视频结尾（沿用现有 ED 跳过行为）。
4. 云端有段时，本检测不参与（沿用现有逻辑）。

## 8. 与现有代码的关系

- 复用：`getBinding`、`performSkip`、`renderPill`、`showToast`、油猴菜单、`intervals` 清理机制。
- 新增：帧抓取（canvas + crossOrigin 注入）、aHash/pHash 与 Hamming 距离、本地指纹存取、采样循环。

## 9. 测试策略

- **纯函数可测**（现有零依赖 test harness）：aHash/pHash 计算、Hamming 距离、阈值判定、连续命中判定、指纹序列化 / 反序列化。
- **帧抓取 / CORS** 依赖浏览器，需集成验证；测试里用假帧数据驱动检测逻辑。

## 10. 范围外（v1 不做）

- 声音指纹。
- 标记的编辑 / 删除面板（换 OP/ED 用「重新标记」覆盖）。
- 上传共享库（Anime Skip）。
- 窗口指纹（若单帧误判多再升级，见 5.2）。
